Full flow: from Add Part to AP POLE and GTOPAS

Every step runs the rules of the proposal Staging Header Order: the save calls SP_STG_WRITE (rows, Superseded, OPERATION_TYPE), [Sync] calls SP_STG_SYNC (0 → 1 only) and starts the RPA parent flow: with GTOPAS rows in the run, XD06 goes first and XD07 starts only when GTOPAS succeeded (scenario 1); without them, XD07 at once (scenario 2); the Period Rollover runs XD06 only. XD07 uploads the files EXPORT_PRE, KANBAN, EXPORT_POST built by the views. AP POLE is simulated too: it keeps a row active until a newer Effective Month / Year and checks every uploaded row (total Max Shipping Box (RCS) of the part ≤ Max Shipping Box Qty), so each upload shows whether it passes.
