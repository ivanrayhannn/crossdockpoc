Full flow: from the save to AP POLE and GTOPAS

Every step runs the rules of the proposal Staging Header Order: the save calls SP_STG_WRITE (rows, Superseded, OPERATION_TYPE), [Sync] calls SP_STG_SYNC (0 → 1 only), the views build the files EXPORT_PRE, KANBAN, EXPORT_POST and the RPA uploads them. AP POLE is simulated too: it keeps a row active until a newer Effective Month / Year and checks every uploaded row (total Max Shipping Box (RCS) of the part ≤ Max Shipping Box Qty), so each upload shows whether it passes.

An Export save without a Kanban change writes the header with 5. The view reads it only for the header sent in the same run as the Export rows of the part.
